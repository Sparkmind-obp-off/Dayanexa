# Capability Foundry

## 1. Purpose
Capability Foundry converts a validated solution requirement into a reliable, reusable ability. It is downstream of demand discovery: lack of current capability must not hide an opportunity.

## 2. Capability options
1. Reuse existing internal capability.
2. Compose existing agents/tools.
3. Build software, workflow, agent, dataset, or operational process.
4. Integrate or license a third-party provider.
5. Contract a qualified human contributor.
6. Partner with an organization.
7. Defer or reject if cost, time, risk, or evidence makes it unjustified.

## 3. Capability record
Capability ID, description, owner, version, inputs/outputs, dependencies, permissions, quality standard, reliability, capacity, latency, cost model, security classification, geographic/legal limits, monitoring, and sunset plan.

## 4. Gap-to-readiness lifecycle
IDENTIFIED → REQUIRED → GAP_CONFIRMED → FORMATION_PLANNED → BUILD_OR_ACQUIRE_APPROVED → IN_DEVELOPMENT → INTEGRATION_TESTING → QUALITY_VALIDATION → AVAILABLE → MONITORED → DEPRECATED or SUSPENDED.

## 5. Build/buy/partner decision
Compare total cost of ownership, time-to-ready, quality, lock-in, data access, security, commercial rights, scale, reversibility, and strategic reuse. Paid acquisition, subscriptions, recruitment, and provider commitments require explicit budget approval.

## 6. Readiness gate
A capability is AVAILABLE only when functional tests, quality tests, permission review, cost measurement, failure handling, monitoring, and documented limits pass. A demo is not production readiness.
